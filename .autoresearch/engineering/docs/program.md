# autoresearch — engineering/docs

## Goal
Maximize `build_status` — the Docusaurus docs site must build cleanly. Target file: `website/sidebars.ts` — the sidebar configuration that drives doc navigation.

Higher build_status is better. Target: 1.0000 (zero build errors).

## Research-Backed Strategies
- **Information Architecture** (Rosenfeld & Morville, 2006): Sidebar structure should follow content hierarchy. Ensure every skill has one unambiguous path.
- **Progressive disclosure** (Nielsen, 2006): Group related skills under clear category labels. Don't flatten everything into one level.
- **Content consistency**: Sidebar labels should match document titles. Mismatches confuse readers and break expectations.
- **Drift detection**: Ensure every sidebar doc ID has a corresponding `.md` file on disk (the checkSidebarsDocIds validation). Any mismatch causes build failures.
- **Generated vs manual**: Sidebar entries generated by `generate-skill-docs.py` vs manually curated sections should be clearly separated to prevent merge conflicts.

## What the Agent Can Change
- Only `website/sidebars.ts` — the single file being optimized.
- Reorder, regroup, relabel sidebar categories.
- Add cross-references between related skills.
- Remove duplicate or orphaned entries.

## What the Agent Cannot Change
- `evaluate.py` — the evaluator is read-only ground truth.
- The actual `.md` doc files — they are generated from SKILL.md sources.
- The Docusaurus config (`docusaurus.config.ts`).
- Any other files in the project.

## Strategy
1. First run: establish baseline. Make no changes.
2. Audit — scan for missing doc IDs, orphaned entries, inconsistent labels.
3. Try the most impactful fix first (most broken links / missing docs).
4. If that works, push further: improve categorization, add cross-links.
5. If stuck, try orthogonal: sort categories logically, fix label casing.
6. Read the git log of previous experiments. Don't repeat failed approaches.

## Simplicity Rule
A small docs improvement that adds complexity is still worth it — this is documentation.
But prefer minimal changes. Fix real problems, don't rearrange for aesthetics.

## Stop When
You don't stop. The human will interrupt you when they're satisfied.
If no improvement in 20+ consecutive runs, change strategy drastically.
